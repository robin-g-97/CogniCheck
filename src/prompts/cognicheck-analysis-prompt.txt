REPORT MATURITY CLASSIFICATION

Before scoring, silently classify the report into one of four maturity levels. Return that level in executive_verdict.maturity_level.

LEVEL 1 - Data dump or spreadsheet-like report
Mostly tables, raw numbers, dense matrices or operational exports. Little visual hierarchy. User must inspect many cells manually.

LEVEL 2 - Operational report
Useful for monitoring and periodic control. Contains structure, filters, references and details, but requires active interpretation.

LEVEL 3 - Analytical dashboard
Clear analytical structure, meaningful comparisons, supporting visuals and some hierarchy. Still requires some interpretation.

LEVEL 4 - Decision dashboard
One clear decision question, strong focal hierarchy, immediate exception detection, low mental reconstruction and clear next-step relevance.

SCORING ATTITUDE

Score strictly. Avoid central tendency bias. Use the full 1-10 range.

Important:
- A professional-looking report is not automatically good.
- A report with many visuals is not automatically a dashboard.
- A report with references, budgets or deltas is not automatically decision-ready.
- A visually polished report can still score low on decision alignment if the user must manually infer the decision logic.
- Distinguish between information relevance and decision readiness. A report can contain relevant information but still fail to actively support a decision.
- Strong section scores require clear evidence that the report supports fast, reliable interpretation and decision-making.
- A 5 or 6 is not a bad score. It often means the report is operationally useful but not yet a strong decision dashboard.
- Always evaluate from the perspective of the intended user's cognitive effort and the stated decision context.
- Do not overfocus on one issue across all sections. If one issue is important, mention it once clearly and then move on.
- Use psychological theory as an explanatory lens, not as academic decoration.

GLOBAL CAP RULES

Apply these rules before assigning scores:

- If the report is mainly a data dump or spreadsheet-like matrix, quality-oriented scores cannot be above 5 unless there is strong contrary evidence.
- If the report is an operational report, quality-oriented scores cannot be above 6 unless there is strong evidence of decision-readiness.
- If there is no clearly identifiable primary decision question, decision_alignment.score cannot be above 6.
- If the user must inspect more than three separate visuals or tables to answer the main question, cognitive_load.score should usually be 7 or higher.
- If deviations are only shown numerically and not visually prioritized, decision_alignment.score cannot be above 6.
- If the report looks polished but the user still has to reconstruct the meaning manually, quality-oriented scores cannot be above 6.
- Quality-oriented scores of 8 or higher require a clear dominant reading path, visual prioritization of deviations and strong reduction of cognitive effort.

NEGATIVE EVIDENCE CHECK

For each score, explicitly check what prevents a high score or creates cognitive/decision risk.

Strong quality-oriented scores require most of the following to be true:
- The main message is visible within 5 seconds.
- Related information is visually grouped.
- The user does not need to mentally combine more than two distant elements.
- Visual emphasis matches business importance.
- Exceptions or deviations are visually encoded, not only shown as numbers.
- The page has one dominant reading path.
- Attention competition is limited.
- Detail supports the main message instead of competing with it.
